# Release notes

One file per release, named after its tag (`v0.1.0-alpha.8.md`), added in the pull request that
prepares the release. Write what changed since the previous release and the scope statement. Do not
write a verification section: the release workflow appends one from the evidence it verified, naming
the source commit, the CI and release runs, the image digest, the attestation, and how the tag was
signed.
